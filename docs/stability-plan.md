# 稳定性验收与诊断计划

本轮以完整解析、可下载和可定位故障为目标，不调整下载通道、解析并发或 UI 布局。

## 实施顺序与完成标准

1. 部署身份与请求关联：后端健康检查提供部署版本；前端构建产出版本文件；错误、成功、续传响应均带服务器生成的请求编号。
2. 解析诊断：记录短链展开、各策略耗时和结果计数，区分完整选择、策略耗尽、超时返回已有资源和主动取消。
3. 自动化验证：并发请求不能串号；日志不包含作品标题、分享文案、媒体签名或原始错误内容；下载仍可流式传输和取消；既有图集、分包和重试测试继续通过。
4. 发布验收：先完成 CI，再部署前后端，记录版本，使用下面的固定样本逐项验收。手机真实保存结果另行确认。

## 固定样本清单

- V1 普通视频：https://v.douyin.com/SG6budQ3QTs/ 。来自历史问题，发布时重新确认链接仍有效；验收单项下载及播放。
- L1 三项实况：https://v.douyin.com/SyamEay-LQo/ 。期望 3 张静态图片、3 个动态轨；动态优先 ZIP 含 3 个 MP4，原图 ZIP 含 3 张图片。
- I1 纯图集：待补公开样本及人工核对的图片数量。
- V2 大视频：待补确认大于 64 MiB 的公开样本；验收转交代理后完整保存，不能只检查是否发出了下载请求。
- E1 失效资源：自动化用上游 403/404/410 和 HTTP 200 HTML/JSON 固定响应验证；公开链接过期不可稳定复现，不凭空指定失效链接。
- B1 分包边界：自动化用较小容量和固定字节流覆盖分包、超限、失败重试与取消；真实手机上的多包保存仍需人工验收。

公开样本会失效，失效时记录原因后更换，不能默默降低期望资源数量。大文件和纯图集样本尚未补齐前，不宣称已覆盖全部真实场景。

## 每次发布的验收步骤

1. 在仓库根目录执行 `npm ci` 和 `npm run check`，确认 Windows/Linux CI 均通过。
2. 部署后访问前端 `/version.json?check=<本次时间>` 和后端 `/api/health`。记录前端 commit、builtAt，以及后端 version、versionTag、versionCreatedAt。两种版本标识含义不同，不直接比较是否相等。
3. 对 V1、L1 和已补齐的 I1/V2 分别解析三次，记录每次耗时和资源数量。速度对比必须注明设备、浏览器和 Wi-Fi/移动网络，不能用单次服务器测试代表手机速度。
4. 手机上分别测试单项保存、动态优先 ZIP、原图 ZIP；解压清点文件并尝试打开图片、播放视频，确认无重复或遗漏。
5. 测试取消后重新解析、网络中断后的批量重试，以及逐包点击保存。已请求浏览器保存不等于文件已保存成功。
6. 若出现缺项、重复、不可打开或无法保存，记录请求编号和版本，先定位问题再发布下一次改动。解析较慢单独记录，不通过删减资源来缩短时间。

## 诊断字段和边界

- 所有 Worker 响应包含 `X-Request-ID`、`X-Worker-Version`，并通过 CORS 暴露。请求编号由服务端生成，不信任客户端同名头。前端解析失败时将可用编号附在错误提示后。
- `request_response`：接口类别、HTTP 状态、返回响应前的耗时。对于下载，它只表示响应已准备好，不代表传输完成或手机已保存。
- `request_error`：受控错误码，不包含原始错误内容；可与同一请求编号的 HTTP 状态关联。
- `resolve_complete`：短链展开耗时及成功、错误或取消。
- `strategy_complete`：策略名称、耗时、结果计数、完整性标志及成功、错误或取消。策略成功不等于资源完整。
- `parse_selection`：结束原因 `complete`、`exhausted`、`timeout` 或 `cancelled`。`complete` 表示满足现有策略选择条件，不是对上游作品完整性的独立证明。
- `parse_result`：最终静态图片、实况视频、普通视频数量。通过请求编号关联到前面的策略事件。
- 应用新增日志不记录原始分享文案、作品标题、完整 URL、签名参数、IP 或原始异常。Cloudflare 平台自身的访问日志有独立采集配置；不要把包含下载 query 的完整平台日志公开转发。
- 后端版本来自 [Cloudflare Version Metadata](https://developers.cloudflare.com/workers/runtime-apis/bindings/version-metadata/)。缺少绑定时显示 `unknown`，不冒充生产版本。版本标签需部署者显式设置；标签缺失不影响版本 ID。
- 前端 `version.json` 优先使用构建环境的 `VERCEL_GIT_COMMIT_SHA`，否则读取 Git HEAD；无法取得时返回 `unknown`。本地含未提交修改时，commit 只标识 HEAD，不代表工作区完全一致。
- 本轮不新增第三方埋点或后台定时采集。响应流中途失败和手机保存失败仍需下载器状态、网络面板及人工复现补充判断。
